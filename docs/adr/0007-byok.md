# ADR 0007: BYOK — users bring their own AI keys

Status: accepted (2026-07-27)

## Context

The agent runs on the Anthropic API; someone must pay per token. An
app-provided key requires usage caps and billing almost immediately.
Anthropic's API does not offer embeddings, so semantic retrieval needs a
separate provider.

## Decision

Users provide their own Anthropic API key, stored encrypted at rest.
Optionally they also provide an embeddings-provider key (Voyage AI).
Without an embeddings key, `find_relevant` degrades gracefully to
lexical + graph-proximity + canon scoring — no semantic component, still
functional. No billing system in v1; a hosted/metered tier can come later.

## Consequences

- Zero AI cost exposure and no payment infrastructure in v1.
- Onboarding friction: users need an API key (two, for full retrieval).
- Key encryption and never-log-keys handling are part of the auth/security
  surface.
- Retrieval quality is tiered by what keys a user configures; the scorer
  must be designed for a missing semantic signal.
